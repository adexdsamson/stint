<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent processes -> one lease/receipt file | multiple writers + readers across processes hit the same files on NTFS (the reproduced EPERM surface). |
| on-disk receipt array -> in-memory chain | a receipt file may be edited or torn between appends. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-06 | Tampering (integrity) | cross-process concurrent writes | high | mitigate | proper-lockfile cross-process mutex + atomic rename + transient retry; cross-process hammer asserts version === 60 with 0 torn reads on Windows CI. |
| T-06-07 | Repudiation | append-only receipt integrity | high | mitigate | store never mutates/reorders existing entries and never computes a hash; `verifyChain` (06-05) recomputes on load, so a tampered file is detected at read time. |
| T-06-08 | DoS | leftover temp/lock artifacts | low | mitigate | in-process hammer asserts no `*.<number>` temp files or `.lock` dirs remain after the run. |
</threat_model>
