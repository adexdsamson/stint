  <options>
    <option id="dir-per-lease">
      <name>Option A — dir-per-lease (RESEARCH-recommended)</name>
      <pros>`leases/&lt;id&gt;/lease.json` + `leases/&lt;id&gt;/receipts/{verified,attested}.json` + `checkpoint-*.json`; `proper-lockfile` scoped per `lease.json` so different leases never contend (honors "same id serialized, different ids concurrent"); receipts co-located per lease (ReceiptStore is per-lease, Pitfall 10).</pros>
      <cons>More directories on disk; two lock scopes (lease vs receipts) to order (always lease-then-receipts).</cons>
    </option>
    <option id="flat-map">
      <name>Option B — single flat leases.json map, one lock</name>
      <pros>Simplest file count.</pros>
      <cons>Rejected: one lock serializes unrelated leases, violating the contract's "different ids concurrent" guarantee.</cons>
    </option>
    <option id="file-per-lease-global-lock">
      <name>Option C — one file per lease, single store-wide lock</name>
      <pros>Fewer lock files.</pros>
      <cons>Rejected: serializes unrelated leases; same contract violation as B.</cons>
    </option>
  </options>
  <resume-signal>Select: dir-per-lease (recommended), flat-map, or file-per-lease-global-lock</resume-signal>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arg / env -> filesystem path | `--store`, `STINT_HOME`, and any `<leaseId>` become filesystem paths; untrusted input crosses here. |
| on-disk JSON -> in-memory Lease | a lease file may be edited, torn, or malformed between writes. |
| concurrent processes -> one lease file | a proxy `run` and a `revoke`/`cleanup` in another terminal contend for the same file (Pitfall 5). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering / Info disclosure | `assertSafeLeaseId` / path join | high | mitigate | Strict id regex + reserved-name reject + `path.resolve`-then-prefix-assert under store root (paths.ts). |
| T-06-02 | Tampering (integrity) | concurrent `transaction()` | high | mitigate | per-id queue + `proper-lockfile` + atomic rename + transient retry; contract suite + Wave-2 hammer prove no lost updates / torn reads. |
| T-06-03 | DoS | compromised/stale lock | medium | mitigate | `onCompromised` records (never throws from timer, Pitfall 3); abort commit if lock lost before write; bounded retries (no infinite loop). |
| T-06-04 | DoS | lock held across approval wait | medium | accept | Documented UX limit; surface typed `LeaseBusyError` + EXIT_CODES.leaseBusy with a clear message (Pitfall 5); do not change dispatch.ts (Phase 4 contract). |
| T-06-05 | Tampering / Repudiation | malformed lease JSON on load | medium | mitigate | shape-validate on load -> typed `StoreCorruptError` (never crash, never return a bad Lease). |
| T-06-SC | Tampering | npm installs (commander, write-file-atomic, proper-lockfile, picocolors, @types) | high | mitigate | RESEARCH `## Package Legitimacy Audit` returned OK/Approved for all six (postinstall null on the four runtime pkgs); no `[ASSUMED]`/`[SUS]` -> no blocking checkpoint required. |
