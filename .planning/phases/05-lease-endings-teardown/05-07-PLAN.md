<objective>
Deliver outcome verification (LIFE-06): the runtime-driven `resource_query` predicate verifier (a verifier-actor synthetic read through the existing vault/connector path, normalized via a runtime-owned row adapter, evaluated by @stint/spec's pure evaluator), the `user_confirm` out-of-band HostAdapter method, and `none` — with the invariant that the agent's own "done" claim only *triggers* verification and never completes a lease. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent signal -> runtime verifier | The agent may only trigger; the runtime runs the verifier — the agent never supplies a completion. |
| verifier read -> customer resource | The synthetic read uses runtime-held credentials via the vault/connector path (no agent-visible tool). |
| read result -> predicate/receipt | Rows are normalized runtime-side; only a closed outcome + stable reason reaches the receipt. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07-S | Spoofing | agent claiming completion / forging outcome_verified | high | mitigate | Agent may only signal; reduce()'s actor check rejects an agent actor; only verifierEvents.outcomeVerified (actor verifier) via runtime evaluation (D-03, D-19). |
| T-05-07-I | Information Disclosure | raw rows/values/credential in a verification receipt or agent response | high | mitigate | Verification receipt carries only outcome + stable reason (D-07); the read reuses the scrub-on-return execute path (Phase 4). |
| T-05-07-E | Elevation of Privilege | verifier read appearing as an agent tool / counting against limits | medium | mitigate | Verifier read is runtime-originated, absent from tools/list, and does not touch limit counters (D-02). |
| T-05-07-SC | Tampering | new package installs | n/a | accept | No new external packages this phase — no legitimacy gate required. |
</threat_model>
