<objective>
Land the two additive shape changes every later Phase 5 task compiles against, before any orchestrator or step code exists: (1) widen the `TeardownStepPayload.outcome` JSON-Schema enum so non-OAuth teardown steps have honest outcome values, and (2) add the optional `Lease.teardownProgress` record that persists per-step teardown progress for idempotent resume.

Purpose: Pitfall 2 / Pitfall 3 — if step implementations are written against the current too-narrow enum, every non-OAuth step's success has no valid outcome; and there is no place to persist D-14 progress without an additive `Lease` field. Sequencing both first means the orchestrator, steps, and their tests all compile against the final shape.
Output: a widened receipt-outcome enum (regenerated types), an additive `Lease.teardownProgress` field with `TeardownStepName`/`TeardownStepOutcome`/`TeardownProgress` types, an exported `makeTearingDownTestLease` fixture, and round-trip + golden-hash tests.
</objective>
