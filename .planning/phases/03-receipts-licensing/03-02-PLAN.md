Output: checkpoint.ts (jose sign/verify, injectable keypair), verifyChain extended with checkpoint anchoring, and the checkpoint conformance vector.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| store -> verifier | A persisted chain plus its checkpoint are untrusted; a shorter internally-consistent prefix must be caught against the signed anchor. |
| key holder -> checkpoint | The checkpoint keypair is injected; core never owns key material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04 | Tampering | verifyChain truncation detection | high | mitigate | Ed25519-signed checkpoint anchors the head hash + count; a truncated chain is detected with reason "truncated" and exact brokenAtSeq (RCPT-06). |
| T-03-05 | Spoofing | checkpoint signature | high | mitigate | verifyCheckpoint restricts algorithms to EdDSA and validates against the injected public key; a forged/invalid signature yields checkpoint_sig_invalid. |
| T-03-06 | Information Disclosure | verifyCheckpoint error path | medium | mitigate | Every failure collapses to a fixed boolean/Result; jose exception text is never forwarded (mirrors jws.ts). |
</threat_model>
