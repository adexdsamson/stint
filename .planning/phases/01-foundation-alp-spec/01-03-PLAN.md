## Signature format decision (follows the user's canonical reference, rated costly)

CONTEXT.md canonical_refs name RFC 7515 Appendix F (detached content) plus RFC 8037 as the manifest signature format. RESEARCH Pattern 4 proposed RFC 7797 unencoded payload (b64 false with crit); that is NOT used, because the user-cited reference is Appendix F and b64 false needs crit-header support that some non-TypeScript JOSE libraries lack.

- JWS protected header: the one shared constant JWS_PROTECTED_HEADER = { alg: "EdDSA" }. Its base64url form is JWS_PROTECTED_B64 = eyJhbGciOiJFZERTQSJ9. No kid in the header: kid lives only in the envelope's signature.kid (D-04), which keeps the header a content-free constant (RESEARCH Pitfall 5).
- Signing input: ASCII(JWS_PROTECTED_B64) + "." + BASE64URL(JCS(manifest) as UTF-8 bytes).
- signature.sig: BASE64URL of the 64-byte Ed25519 signature over that input (86 characters, no padding).
- jose usage: FlattenedSign over the JCS bytes with setProtectedHeader(JWS_PROTECTED_HEADER), keep only the signature; verify with flattenedVerify({ protected: JWS_PROTECTED_B64, payload: base64url(JCS bytes), signature: sig }, key, { algorithms: ["EdDSA"] }).
- Content hash (D-02, prefix chosen under Claude's discretion): "jcs-sha256:" + lowercase hex SHA-256 of the JCS UTF-8 bytes. The prefix names both the canonicalization and the digest, so implementers cannot mistake it for a hash of raw file bytes (the common sha256: prefix usually means raw bytes, as in OCI digests).

## verifyEnvelope procedure (exact order; ALP.md section 5 in plan 01-05 restates it normatively)

1. validateEnvelopeShape(envelope); on failure return its errors (paths relative to the envelope root, for example /signature/kid).
2. Read manifest.publisher.id with plain typeof checks (the manifest is not validated yet): missing gives missing_required at /manifest/publisher/id, non-string gives invalid_type there.
3. Look up the publisher in trustStore with Object.hasOwn (never bracket access alone, so ids like "__proto__" or "constructor" cannot reach Object.prototype): absent gives unknown_publisher at /manifest/publisher/id.
4. Look up signature.kid under that publisher with Object.hasOwn: absent, or an entry whose kty is not "OKP", crv not "Ed25519" or x not a string, gives unknown_key at /signature/kid. Import only { kty, crv, x } so a stray private "d" member is never used.
5. canonicalize(envelope.manifest); a CanonicalizationError gives not_canonicalizable at /manifest.
6. Verify the detached signature over the JCS bytes; false or any thrown error gives invalid_signature at /signature/sig with a fixed message.
7. Parse the canonical text with JSON.parse; this reparsed value, never the caller's object, is the trusted manifest (RESEARCH Pattern 4, canonicalize README).
8. validateManifest(trusted); on failure return its errors with every path prefixed by /manifest.
9. contentHash = jcs-sha256 of the same JCS bytes used in step 6.
10. Deep-freeze the trusted manifest and mint the VerifiedManifest.

parseEnvelope(raw): byte length (UTF-8 for strings) above MAX_ENVELOPE_BYTES gives envelope_too_large at path "" before any parsing; a JSON.parse failure gives invalid_json at path "" with a fixed message that never echoes the parser text.
