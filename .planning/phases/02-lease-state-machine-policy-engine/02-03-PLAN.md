<objective>
Build the pure policy engine and the runtime-owned connector bindings — the code, outside the model, that decides allow / deny / require_approval for a single call, and the separate pure check that reports when the error window is exceeded. This closes PRXY-02 (a call with no binding is denied), PRXY-03 (classification comes only from bindings, never the manifest), the per-call-expiry half of LIFE-04 (`evaluatePolicy` denies past-expiry calls with no timer), and LIFE-07 (N denials/errors in a window trip the threshold; N-1 do not).

Per D-09 the policy engine is two pure functions: `evaluatePolicy(...)` decides one call, and `checkErrorThreshold(...)` reports whether the window is exceeded; when the latter trips, the CALLER feeds a `policyEvents.errorThresholdExceeded()` event to `reduce` (the actual state advance to `failed` is the reducer's job, 02-02). "Decide a call" and "advance state" stay cleanly separated.

Purpose: this is the allow/deny brain the Phase 4 proxy routes every live `tools/call` through; being pure and clock-injected makes the whole security surface deterministically testable with no real timers.
Output: `bindings.ts`, `policy.ts`, and their test suites.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent tools/call → policy decision | Every call the Phase 4 proxy receives is decided here; the agent must not influence the decision. |
| manifest content → tool classification | A malicious/mislabeled manifest must not be able to reclassify a tool. |
