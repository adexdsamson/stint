<objective>
Bind the consented manifest hash to the lease and guard the activate and resume paths (LIFE-03). A `Lease` persists only the prefixed content-hash string captured at consent (D-20); at activation and on any runtime resume, the presented `VerifiedManifest` is re-hashed via `@stint/spec` and string-compared against that bound hash by one shared pure guard (D-21). A mismatch at activation yields `activation_failed` (actor `runtime`); the same mismatch on resume yields `runtime_failure` (actor `runtime`), per ALP.md §7.4/§7.5.

Purpose: this is the safety-critical check that a lease cannot be activated or resumed against a manifest the user never consented to; keeping the re-check inside the tested pure core (not the caller) means no future caller can forget it.
Output: `hash-guard.ts` (`verifyBoundHash`) and `activate.ts` (`activateLease`, `resumeLease`), with tests.

Note: acquiring delegated grants and issuing the license are the other activate guards in ALP.md §7.4, but they are I/O and belong to Phases 3-4. This plan implements only the pure content-hash guard; the grant/license preconditions are wired by later phases before they call `activateLease`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consented manifest hash → activation | The lease may only activate against the exact manifest the user consented to. |
| resumed lease (post-restart) → running manifest | On resume, the running manifest must still match the consented hash or the lease fails. |
| caller-supplied VerifiedManifest fields → hash decision | A tampered `.contentHash` must not be trusted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-01 | Tampering | activating against a swapped manifest | critical | mitigate | verifyBoundHash recomputes and string-compares; mismatch → activation_failed; re-check lives in the pure core, not the caller (D-21). |
| T-02-04-02 | Tampering | resuming a running lease against a swapped manifest | high | mitigate | resumeLease uses the same guard; mismatch → runtime_failure (ALP.md §7.5). |
| T-02-04-03 | Spoofing | trusting a caller-supplied `.contentHash` field | medium | mitigate | Guard recomputes from `.manifest` via hashManifest, never trusts `.contentHash`; tested with a tampered field. |
</threat_model>
