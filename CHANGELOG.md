# Changelog

## 0.2.0 (unreleased)

All `@stint/*` packages publish together as 0.2.0 when v0.2 ships. Nothing in this section has been published yet.

### Added

- `@stint/runtime`, a host-agnostic runtime with four entry points: `createLeaseRuntime`, `resolveTeardown`, `settleExpired` and `runSweep` (below). It is marked experimental: the package description, its README and the JSDoc of each entry point say so, and there is no stability promise before 1.0.
- Four ports in `@stint/core` (secret store, key provider, lease artifact store and telemetry), with in-memory doubles and contract suites in `@stint/core/testing`.
- Credential kinds and per-credential clients: a credential can be an OAuth grant or an API key, and an OAuth grant carries its own client id and revocation endpoint, so a later revoke or cleanup needs no run profile.
- Durable credential custody. Credentials are copied into a secret store, a refreshed token is written back during a run, and cleanup revokes the current grant without a credentials file. Until the keychain store arrives the store is a plaintext file store, and every command that writes a credential says so on stderr.
- `stint-cli create --credentials <file>`, which seeds the store after consent, with the custody statement and a separate acknowledgement for a credential that cannot be revoked.
- `stint-cli run` serves a lease from the store alone once every expected credential is there, and tells you on stderr, when a credential first arrives, that one which cannot be revoked stays valid until you rotate it at the provider.
- The `teardown_blocked` receipt kind and the optional `resource` field on per-credential teardown receipts. Both are additive under `alp/0.1`.
- `stint-cli supervise`, the eighth command. It looks after every lease in one store with no other user action. It settles a lease whose time ran out and tears it down, tears down ended leases, retries a `cleanup_incomplete` lease on a backoff, resumes a teardown that a crash cut short, probes idle leases for a grant the provider revoked, reports lease records it cannot read and pauses lease expiry after a forward jump of the system clock. Without flags it runs until it is stopped, and Ctrl-C finishes the step in flight, releases its locks and exits 0. `--once` runs one sweep and exits. Only one supervisor runs per store, and a second one exits 8.
- The `supervise` flags, each a whole number of seconds unless noted: `--sweep-interval` (default 30), `--retry-base` (60), `--retry-max` (3600), `--retry-cap` (a count, 8), `--probe-interval` (900, and 0 turns probing off), `--corrupt-repeat` (86400) and `--clock-jump-threshold` (3600), plus `--once`, `--confirm-clock` and the global `--store` and `--json`. A bad value is a usage error (exit 2) that names the flag.
- `supervise --once` exit codes for cron: 0 when nothing is left to do, 7 when a lease is stuck, 10 when a lease record is corrupt or the clock pause marker cannot be read (10 wins over 7), and 8 when another supervisor holds the store or the lock was lost.
- `supervise --confirm-clock`, which confirms the system clock after a reported forward jump. It takes no lock and asks nothing, and the running supervisor resumes settling expiry on its next sweep. The pause and the confirmation are the files `supervisor/clock-pause.json` and `supervisor/clock-confirm.json` in the store.
- An operator guide for `supervise` in `packages/cli/README.md`, with setups for Windows Task Scheduler, a systemd user unit, a launchd agent and cron. Setting up a background service is documentation only. There is no install command.
- `runSweep` in `@stint/runtime`, with `createSweepState` for the state a host keeps between sweeps. One call runs one store-driven sweep: settle, tear down, retry, probe and report. The host owns the loop, the timers and the signals. The supporting pieces (`DEFAULT_SUPERVISOR_CONFIG`, `deriveRetryState`, `markStuck`, `probeLeaseGrants`, the run heartbeat helpers, the clock guard helpers and `createInMemorySupervisorControl`) are exported too.
- `stint-cli run` ends its own lease. When the lease ends for any reason (`expired`, `revoked`, `completed`, `failed` or `unavailable`), the run prints `stint: Lease ended (<reason>); stopping.` on stderr, tears the lease down under the fence and exits 0, with no supervisor running. A run also writes a `run_heartbeat` artifact every 10 seconds, so the supervisor never probes beside it, and probes its own idle grant every 900 seconds.
- The `teardown_takeover` and `teardown_stuck` receipt kinds. Both are additive under `alp/0.1`. `stint-cli receipts` shows them as `teardown takeover: epoch <n> -> <n> (fence_expired)` and `teardown stuck: <reason> after <n> failed attempts`.
- A stuck lease is labelled in `stint-cli inspect` as `<state> (stuck: <reason>)`. The reasons are `credentials_unavailable`, `retries_exhausted`, `revocation_failed` and `manifest_invalid`, and the supervisor prints the fix for each. There is no command to abandon a stuck lease.

### Changed

- A credential that cannot be revoked at the provider now ends the lease as `cleaned_up` with a caveat (`cleaned_up (credential not revoked upstream)` and one rotate line per resource) instead of `cleanup_incomplete`. The exit code is 0. ALP Section 10 records `discarded_revocation_unsupported` as terminal success with a caveat.
- An approval wait no longer holds the lease lock. `revoke`, teardown and other calls proceed while a person decides. A call approved after the lease expired or ended, or after a limit was reached, is now denied instead of executed, and the terminal says so.
- A teardown whose recorded credentials are missing from the store is blocked with exit 2 and a `teardown_blocked` receipt. The lease is left unchanged and the message names the command that supplies the credentials.
- Teardown and receipt appends are concurrency safe: a teardown pass runs inside the lease transaction, and a receipt append that would break the chain is rejected rather than forking it.
- `stint-cli create`, `run`, `revoke` and `cleanup` are thin hosts over `@stint/runtime`. `runLease` is still exported from `@stint/cli` with the same options.
- Teardown is fenced. A driver (a supervisor, a running lease or a user command) holds a fence on the lease record before it runs a step. The fence is an epoch with a 120 second expiry, renewed at every step and released in the same write that lands the pass. A driver may take over a fence that expired, and the takeover is receipted with `teardown_takeover`. A step that is already recorded never runs again. ALP Section 10 states these driver rules, and Section 7.5 notes that per-call enforcement never depends on a sweep. This closes the Phase 8 known limit: a second driver can no longer join a teardown already in flight.
- `stint-cli revoke` and `stint-cli cleanup` wait up to 30 seconds for another driver's live fence. If it is still held, they exit 8 with `Another process is tearing down this lease. Wait for it to finish, then run: stint-cli cleanup <id>`. A `revoke` that exits 8 leaves the lease `revoked`.
- The token-error classifier reads the HTTP status. `invalid_grant` means revoked only with a 4xx status other than 429, and a 401 `invalid_token` means revoked. A 5xx or 429 with an `invalid_grant` body, a network error, a timeout and a 401 `invalid_client` are transient and never end a lease. A transient answer's `Retry-After` header is honoured.
- Every OAuth refresh and RFC 7009 revocation request times out after 15 seconds (`DEFAULT_OAUTH_TIMEOUT_MS`). A hung token endpoint is a transient error, and a hung revocation endpoint is a failed revocation.
- `stint-cli run` exits 0 after it stops because its lease ended. Before, it kept serving until the agent disconnected.

### Breaking changes

- `SeededCredential` (`@stint/proxy`) is now a union of `OAuthSeededCredential` and `ApiKeySeededCredential`. It was an interface. Code that reads `accessToken` from a `SeededCredential` must narrow with `isApiKeyCredential` or use `OAuthSeededCredential`. `refreshAccessToken` now takes an `OAuthSeededCredential`.
- `createCredentialVault` takes an `OAuthClient` or an `OAuthClientResolver` first and a `CredentialVaultOptions` third (a superset of `RefreshOptions`, with a new `secrets` option). `revokeAndDiscardLeaseCredentials` takes an optional third parameter, `expectedResources`.
- `CredentialVault.discardLeaseCredentials` returns `void | Promise<void>` instead of `void`. It returns a promise only when the vault has a secret store.
- `LoadedCredential` (`@stint/cli`) is now a type alias of `OAuthSeededCredential`. It was an interface extending `SeededCredential`.
- `ReceiptStore.append` must reject with `ReceiptConflictError` when `entry.seq` differs from the number of entries stored for the chain. A third-party receipt store must add the check, and a caller that appends hand-built entries must supply the right `seq`. The `chain` parameter of `appendCallReceipt` is ignored.
- `createDefaultTeardownSteps` takes a sixth optional parameter, `options` (`expectedResources` and `secrets`). `TeardownDeps` gains an optional `credentialCheck`, and `runTeardown` and `retryTeardown` can reject with `TeardownBlockedError` when it is set. A failing durable discard or a leftover secret now makes step 4 `failed` and the lease `cleanup_incomplete`.
- `ReceiptEntry` has a new kind, `teardown_blocked`. Code that switches exhaustively over the receipt kinds must handle it.
- `ApprovalDecision` can now deny with the reasons `lease_ended` and `approval_queue_full`, in addition to `user_denied` and `timeout`. `LifecycleEvent` has a ninth member, `approval_void`. `ApprovalStage.requestApproval` takes an optional fourth parameter, and `ProxyDeps` gains optional `approvalWatchMs` and `telemetry`. A host that switches exhaustively on any of these must handle the new values.
- Inside `@stint/cli`, `reportTeardown` is now asynchronous and takes the store root, `buildTeardownDeps` and its mixed authorization server refusal are removed in favor of `resolveTeardown`, and the `LeaseBusyError` message now reads "The lease is busy: another operation holds it. Wait a moment, then retry." These are not exported from the package index.
- `LeaseStore.scan()` is required. It returns every lease sorted by id, and a record it cannot read comes back as `{ id, unreadable, fingerprint }` without the file being touched. A third-party lease store must implement it. The contract suite in `@stint/core/testing` covers it.
- `LeaseArtifactName` has a fourth member, `run_heartbeat`. A third-party artifact store must store it.
- `ReceiptEntry` has two new kinds, `teardown_takeover` and `teardown_stuck`. Code that switches exhaustively over the receipt kinds must handle them.
- `LifecycleEvent` has a new member, `teardown_stuck`, carrying a `TeardownStuckReason`. A host that switches exhaustively on it must handle the new value.
- `CredentialVault` has a new method, `probeGrant`, which runs one real refresh-token exchange and returns a `ProbeGrantResult` (`ok`, `provider_revoked`, `transient` or `not_probeable`). A hand-written vault must implement it.
- `TelemetryEvent` has new variants: `teardown.fence_takeover`, `supervisor.action`, `supervisor.probe`, `supervisor.corrupt_record`, `supervisor.clock_paused` and `supervisor.expiry_paused`. A sink that switches exhaustively must handle them.
- The `transient_error` variant of `RefreshResult` carries an optional `retryAfterSeconds`.
- `RunningLease`, returned by `createLeaseRuntime`, has a new member, `ended`, a promise that resolves when the lease ends and the run has dealt with it.
- The CLI registers an eighth command, `supervise`.

### Known limits

- The one teardown step that was in flight when a driver crashed may run again when the next driver takes over. Every recorded step is safe, but a publisher cleanup hook should be safe to call twice.
- A credential whose revocation failed leaves the lease stuck with `revocation_failed` until you rotate the credential at the provider and run `stint-cli cleanup`. Stint drops its own copy after the attempt, so a retry cannot help. A retryable revoke is deferred.
- The clock guard compares the wall clock with a monotonic clock between two sweeps. On Linux and macOS the monotonic clock stops while the machine sleeps, so a sleep longer than `--clock-jump-threshold` looks like a forward jump and pauses expiry until you run `stint-cli supervise --confirm-clock`. A `--once` run and a freshly started supervisor have no earlier reading, so they cannot detect a jump, though they honour a pause already recorded. A backward jump is not detected.
- `supervise --once` keeps no memory between runs. Under cron each run probes every idle lease whose last activity is older than `--probe-interval`, re-reports every corrupt record and re-announces every stuck lease.
- A single `invalid_grant` answer to a probe ends the lease. A grant that is not really gone can therefore end a lease when the provider expires refresh tokens after a period of inactivity, when the provider or the account restricts sign-in by IP address or by login hours, or when a provider outage answers `invalid_grant` instead of a 5xx. Raise `--probe-interval` or pass `--probe-interval 0` for such a provider.
- The supervisor stops cleanly on SIGINT, SIGHUP and, on Windows, SIGBREAK. SIGTERM, SIGKILL, Task Scheduler "End" and `taskkill` are hard stops. They are recovered by the fence lapsing after 120 seconds and the supervisor lock going stale after 10 seconds, so the teardown in flight is delayed but not lost.
- On Windows, a Ctrl-C that arrives during startup — while Node is still loading modules, or before the supervisor has taken the store lock — is handled by the OS default console handler, not by the supervisor: the process stops at once and PowerShell reports exit code -1073741510 (`0xC000013A`, STATUS_CONTROL_C_EXIT). Nothing is corrupted; a lock left behind goes stale and the next start recovers it. The stop listener is installed before the store is opened, so only module loading remains in that window. A second Ctrl-C during the graceful stop is the immediate stop, which is exit code 1 on Windows.
- Credentials are stored unencrypted on disk until the keychain store arrives in Phase 12. On Windows the file is protected only by your user profile.
- API key grants are recorded only in the per-lease grants record, not in the manifest, so an edited or deleted grants record cannot be recovered for an API key.
- A step's side effects now run before its receipt inside one transaction. If the receipt append fails after the step ran, that pass does not record the outcome and the step runs again on the next pass.
- `stint-cli run` shows the notice for a credential that cannot be revoked on stderr and does not wait for an answer, because stdout is the MCP channel and a prompt would stop headless runs. The separate acknowledgement happens at `create --credentials`.
